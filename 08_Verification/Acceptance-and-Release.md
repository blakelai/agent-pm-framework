# Acceptance, release and operations

Trace REQ to PBI, numbered AC, test case and actual test run. Keep test design separate from execution, and record environment, build, actor, time, requirement fingerprints and inspectable evidence. Simulation is not a passed product test.

Business owners define UAT scenarios, acceptance measures and the treatment of remaining defects. Migration requires reconciliation totals, rejected-record handling, repeatability and rehearsal. Security/access and integration exceptions need evidence appropriate to their risks.

Plan the release window, dependencies, owner, cutover steps, checkpoints, communications and explicit go/no-go decision. Define rollback triggers, procedure, data implications and responsible people. Hand over monitoring, support, runbooks, incident escalation, training and known limitations.

Record actual release scope, PBIs and test runs. Keep done, UAT acceptance and released distinct. Review post-release incidents and outcome measures; feed lessons into the backlog. The tool tracks records, not deployment execution.
