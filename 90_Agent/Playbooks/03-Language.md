# Ubiquitous Language

Apply [Evidence and Clarification Policy](../Evidence-and-Clarification-Policy.md) whenever information is unclear, missing or conflicting. Ask the user for clarification or relevant material; keep dependent conclusions pending and continue only supported independent work. This condition also applies to the completion criteria below.

1. Read Settings, Language Policy, CONTEXT-MAP and applicable contexts. Compare meanings with concrete examples; distinguish synonyms from terms with different meanings in different contexts.
2. Add source-backed candidate terms as draft. Keep canonical terms, brief definitions and stable block IDs in CONTEXT; put code/data-field mappings in Code-Mappings. Include Avoid entries only for aliases explicitly deprecated by source evidence or an actual terminology decision. When aliases are not supplied, omit the Avoid line and record that gap under unresolved meanings; a template slot does not authorize invented synonyms.
3. Author definitions in document_language; preserve original aliases, quoted text and code identifiers. Apply terms by context, not by global substitution. Formal consensus requires an actual decision record.
4. For a baselined meaning change, create a new versioned draft and run impact LANG-ID. Assess affected requirements, PBIs, contracts and tests using the baseline/change procedure.

Complete when each term has one authoritative context and evidence, conflicts have owners and needed dates, and the changed scope uses consistent terms. Run validate and review semantics manually.
